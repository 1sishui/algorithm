## 怎么跑（两种方式，任选）

**方式一（最省事）：双击 `算法学习智能体-离线版.html`**

所有代码都打包进这一个文件，不依赖 Python、不依赖网络，双击直接用浏览器打开。
适合给老师、同学演示，也适合拷到 U 盘里带走。

**方式二：双击 `启动.bat`**

它会调用 `serve.py` 起一个本地服务，自动打开 http://127.0.0.1:8123/ 。

> 会弹出一个黑色窗口，那是服务本身，**别关**；关掉网页就打不开了。
> 端口 8123 被占用时，脚本会提示并直接打开已有服务。
> 电脑上没有 Python 时，脚本会自动改用离线版打开。

**两种方式有什么区别**：离线版是打包产物，改了 `src/` 里的源码后需要重新生成（让我来跑 `tools/build-offline.mjs`）；`启动.bat` 直接读源码，改完刷新浏览器就能看到效果，适合开发时用。

## 现在能做什么

- 选择算法：排序（快排/冒泡/插入）、二叉树（前/中/后序）、图（BFS/DFS），共 9 个
- 播放、暂停、上一步、下一步、拖进度条、调速度（键盘：空格 / ← / →）
- 自定义输入数组（逗号分隔，最多 60 个元素）
- 输入跟着视图变：数组填数字、树填层序数组（空位 null）、图填边列表（`A-B, A-C`）
- 树遍历会显示：节点按访问顺序变绿、当前节点高亮、栈里的内容实时更新
- 点左侧知识图谱的节点切换知识点；没有模板的节点会提示“建设中”
- 右侧「错误诊断」：粘贴一段错误代码，返回结构化的诊断结果
- 右侧「理解度评估」：六维演示数据，播放完会小幅变化

## 写自己的算法 → 可视化运行

页面下方有个「写我自己的算法」面板。写一个 `function run(a, viz)`，点运行就能像内置算法一样播放。

```js
function run(a, viz) {
  for (let i = 0; i < a.length - 1; i++) {
    for (let j = 0; j < a.length - 1 - i; j++) {
      viz.compare(j, j + 1, `比较 ${a[j]} 和 ${a[j + 1]}`);
      if (a[j] > a[j + 1]) viz.swap(j, j + 1, '逆序，交换');
    }
    viz.markSorted(a.length - 1 - i, `第 ${i + 1} 轮结束`);
  }
  viz.done('排序完成');
}
```

可用的 API：

| 调用 | 作用 |
|---|---|
| `viz.compare(i, j, 说明)` | 高亮两个位置，计一次比较 |
| `viz.swap(i, j, 说明)` | 交换两个位置并记录 |
| `viz.set(i, 值, 说明)` | 给某个位置赋值（计数排序、堆调整会用到） |
| `viz.markSorted(i, 说明)` | 标记该位置已就位（变绿） |
| `viz.show(说明, {compare, swap, pivot})` | 完全自定义一步 |
| `viz.done(说明)` | 收尾，全部标记为已就位 |

`a` 就是上方输入框里的数组，可以直接改。代码保存在浏览器本地（localStorage），刷新不丢。

**三个必须知道的限制：**

1. **只能写 JavaScript**。浏览器跑不了 C++；JS 的语法和 C 很接近，循环、数组、`if` 基本照抄。
2. **没有“自动”可视化这回事**。任何语言都不可能自动知道算法走到了哪一步，必须在关键位置调用 `viz.*` 上报状态——这和本项目“用行为数据刻画理解过程”是同一个思路。
3. **上限 3000 步**，死循环会被拦下并提示，不会把页面卡死。代码在本机浏览器里运行，别粘贴来路不明的代码。

### 运行记录（第一份真实行为数据）

面板下方会自动记录每次运行：算法名、输入规模、步数、比较/交换次数、耗时、是否出错，最多保留 50 条。

- **导出 JSON**：`schema: algo-agent.runs.v1`，可以直接当论文里的日志样例
- **按算法统计**：面板上方有条形图，显示各算法跑了几次、错了几次，悬停看平均步数与耗时
- 数据存在浏览器 localStorage，换电脑/清缓存就没了；接 Supabase 时把 `saveRecords` 换成写库即可

这条记录是理解度评估的原料：六维特征（修正轮次、思路多样性、难度爬升……）都从这类运行日志里算，而不是拍脑袋写死。

## AI 诊断（同步后自动生成）

六维数字由本地规则算（可复现），**解读交给大模型**——规则写不出“这说明你该练什么”。

绑定 Cookie、同步记录成功后，右侧会自动请求一次分析（约 2–5 秒），输出：

- **一句话总结**：当前水平与主要问题（不出现分数）
- **强势 / 弱势算法**：点名具体算法（动态规划、图论……），依据题目标签统计；没有标签时说明「尚未获取题目标签」
- **建议**：最多 3 条，具体到练哪类算法、什么难度
- **纠错风格**：小步调试 / 频繁重写 / 一次通过

> 报告里不出现任何分数：分数只在内部计算，给用户看的是「哪里强、哪里弱、下一步练什么」。
> 想要「强势/弱势算法」，先点一次「抓取题目标签」（逐题请求，100 道题约 20–30 秒，抓过会缓存）。

面板上有「同步后自动分析」开关，关掉就不会每次同步都花钱。提示词里明确要求：

1. 只依据给出的数字，不许编
2. 分数为 null 的维度视为“数据不足”，不得据此下结论
3. 不说“多练习”这类废话

失败时回退成一句人话（没配 key / 超时 / 旧版服务），不影响六维数字本身。

## 洛谷做题数据（Cookie 绑定）

洛谷的 `/record/list` 接口在没有登录态时直接返回 401，公开抓取这条路走不通，所以采用 Cookie 绑定：
**你只贴两个值，数据由本机服务代取，Cookie 不出本机。**

怎么拿：

1. 登录洛谷 → 按 **F12** → 切到 **Network** → 刷新页面
2. 点任意一条 `luogu.com.cn` 请求 → 右侧 **Request Headers** → 找到 `Cookie:`
3. 里面会有 `__client_id=xxxxx; _uid=123456; ...`
4. 把 `__client_id=` 后面那段填进第一个框，`_uid=` 后面的数字填进第二个框

点「保存并同步」，之后每 10 分钟自动同步一次（页面在后台时跳过）。

安全性：

- 两个值只存在本机浏览器（localStorage），只发给 `127.0.0.1:8123`
- 本机服务再转发给洛谷，日志里只记 uid/page/结果，**不打印 Cookie**
- 面板有「清除」，退出洛谷登录后 Cookie 会自动失效
- 不要截图发给别人，也不要提交进 Git

失败时状态栏会直接说原因：

| 提示 | 含义 |
|---|---|
| 洛谷返回 401 | Cookie 失效或复制不全，重新登录再复制 |
| 记录为空 | `_uid` 不对，或该账号没有提交 |
| 连不上本地服务 | `启动.bat` 的窗口没开，或还是旧版本 |
## 六维特征（v0：从运行记录推算）

右侧「理解度评估」的六个数字**不再是假的**，全部由本机运行记录算出，公式公开：

| 维度 | 怎么算 | 说明 |
|---|---|---|
| 错误修正 | 出错后同一算法的下一次是否成功：`30 + 60 × 修正率` | 无错时给 70 分（无法观察修正行为） |
| 题型迁移 | 已练类别里“用过的算法 / 该类可用算法”的均值 × 成功率系数 | 同类练得越广越高 |
| 思路多样性 | 算法使用分布的归一化信息熵 | 只用一种算法 → 0 |
| 尝试模式 | 每次练习（间隔 > 30 分钟切开）的平均运行轮数，6 轮记满 | 反复迭代得分高 |
| 覆盖均衡 | 各大类练习量分布的归一化熵 | 只练一类 → 偏低 |
| 难度爬升 | 输入规模对时间序号做线性回归的斜率 | 50 为持平，越高越敢上规模 |

**必须说清楚的三点**（写论文时也要这么写）：

1. 这些是**行为代理指标**，不等于“理解度真值”；真值要靠人工标注，那是下一步。
2. 数据不足时显示 `—`，不编数字；样本少于 20 条时面板标“置信度偏低”。
3. 每个分数悬停能看到计算依据，答辩时可以直接念。

## 接大模型（诊断面板）

**不配 key 也能用**：诊断走本地 5 条规则，结果右上角标「本地规则」。

要接真模型，三步：

1. **拿 key**（以 DeepSeek 为例）：打开 platform.deepseek.com → 注册登录 → API keys → 创建 → 复制那串 `sk-...`。其他家（通义 / Kimi / 智谱）同理。
2. **填到 `.env`**：把项目根目录的 `.env.example` 复制一份改名为 `.env`，把 key 填进 `LLM_API_KEY=` 后面。
3. **重启服务**：双击 `启动.bat`。窗口里出现 `Key：已配置` 就成功了。

诊断结果右上角会变成 `大模型 · deepseek-chat · 1240 ms`。

- **换模型**：改 `.env` 里的 `LLM_BASE_URL` 和 `LLM_MODEL`，`.env.example` 里写了通义/Kimi/智谱的地址。
- **成本**：一次诊断约 800–1500 token，deepseek-chat 约 0.002–0.005 元/次；1000 元经费够跑很久，日常开发用不到几块钱。
- **安全**：key 只在服务端（`serve.py`）里用，浏览器拿不到；`.env` 已被 `.gitignore` 排除，别提交。
- **上线版**：`supabase/functions/diagnose/index.ts`，部署命令写在文件开头。

### 诊断还是显示「本地规则」怎么办

点诊断面板下面的 **「测试连接」** 按钮，它会直接告诉你卡在哪一环：

| 页面提示 | 原因 | 怎么修 |
|---|---|---|
| 连不上诊断服务 | 服务没启动，或页面是离线版 | 双击 `启动.bat`；确认地址栏是 `127.0.0.1:8123` 而不是 `file://` |
| 诊断服务返回 501 | 端口上跑的是**旧版服务**，没有 `/api/diagnose` 接口 | 双击 `启动.bat`（会自动关掉旧进程再启动） |
| Key：未配置 | `.env` 没找到，或文件名写成了 `.env.txt` | 确认 `.env` 就在 `algo-agent` 文件夹里，不是 txt |
| 模型接口报错 401 | key 不对：不是这家的 key，或复制少了几位 | 回平台复制完整 key；DeepSeek 官方 key 是 `sk-` 开头、约 35 位 |

> 早期版本用系统默认证书访问 https 会报 `CERTIFICATE_VERIFY_FAILED`，已改为使用 `certifi` 证书包；如果你的环境仍然报错，可以在 `.env` 里临时加一行 `LLM_INSECURE_TLS=1`（仅本机调试，不要提交）。

## 加一个算法要改哪里

1. 在 `src/algorithms/` 下新建文件，导出 `meta` 和 `run(input)`；
2. `run` 返回步骤数组，每步形如：
   ```js
   { array, sorted, pivot, compare: [], swap: [], depth, note, metrics: { comparisons, swaps } }
   ```
3. 在 `registry.js` 里 import 并登记一行。

**UI、播放器、渲染器一行都不用改。**
